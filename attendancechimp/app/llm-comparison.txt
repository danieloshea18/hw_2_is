When comparing the code that I wrote for AttendanceChimp’s models.py versus what Gemini created, I noticed several key distinctions. In the InstructorProfile and StudentProfile classes, Gemini used OneToOneField field types with Django while I used IntegerField field types in each of these classes. Gemini included helper functions to retrieve different types of information such as usernames, enrolled courses, and attendance calculations. While I had predefined a course id within the Course class as an IntegerField primary key, the LLM did not define a primary key, instead leaving this to Django to determine. For Enrollment, Gemini included a nested class in order to pass metadata to Django ensuring unique pairs of students and their courses. I had instead made use of two foreign keys in order to establish this necessary relation. Overall, Gemini’s implementation of AttendanceChimp is more complex as well as complicated to implement. This can especially be seen in QRCodeUpload where an intricate photo upload process is established using the ImageField, for example.
