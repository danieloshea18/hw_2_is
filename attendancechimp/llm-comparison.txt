When comparing the code that I wrote for AttendanceChimp’s models.py versus what Gemini did, I noticed several key distinctions. In the InstructorProfile and StudentProfile classes, Gemini used helper functions to display user-related information. Gemini consistently utilized helper functions to retrieve different types of information such as enrolled courses and attendance calculations. While I had predefined a course id within the Course class as an IntegerField primary key, the LLM did not define a primary key, instead leaving this to Django to determine. Also within the Course class, the LLM used help text to establish a way of defining strings that could effectively represent meeting schedules. For Enrollment, Gemini included a nested class in order to pass metadata to Django ensuring unique pairs of students and their courses. I had instead made use of two foreign keys in order to establish the necessary relation between students and their courses. Overall, Gemini’s implementation of AttendanceChimp is a bit more complex as well as complicated to implement. This can be seen, for example, with the LLM’s decision to verify QR code uploads in QRCodeUpload.
